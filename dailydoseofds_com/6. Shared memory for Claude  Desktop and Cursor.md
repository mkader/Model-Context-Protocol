##  MCP-powered shared memory for Claude Desktop and Cursor

* Developers use Claude Desktop and Cursor independently with no context sharing or connection.
* In other words, Claude Desktop (an MCP host) has no visibility over what you do in Cursor (another MCP host), and vice versa.
* Add a common memory layer to Claude Desktop and Cursor so you can cross-operate without losing context.

* Our tech stack:
  - ​[Graphiti MCP](https://github.com/getzep/graphiti)​ as a memory layer for AI Agents.
  - Cursor and Claude Desktop as the MCP hosts.

* Workflow 
  - User submits a query to Cursor & Claude. 
  - Facts/Info are stored in a common memory layer using Graphiti MCP. 
  - Memory is queried if context is required in any interaction. 
  - Graphiti shares memory across multiple hosts.

    - Deploy the Graphiti MCP server using Docker Compose. This setup starts the MCP server with Server-Sent Events (SSE) transport. 
    - The Docker setup above includes a Neo4j container, which launches the database as a local instance. 
    - This configuration lets you query and visualize the knowledge graph using the Neo4j browser preview.

### Code
  ```
  graphiti/mcp_server/              <-- RECOMMENDED WORKING DIRECTORY
  ├── .env                          <-- KEEP THIS ONE (Fill with API keys & Versions)
  └── docker/
      └── Dockerfile                <-- Keep this here (Do not place a .env in this folder)
      ├── docker-compose.yml            <-- Move your compose file up here if it isn't already
  ```
* clone repo
  ```
  git clone https://github.com/getzep/graphiti.git
  cd graphiti/mcp_server
  uv sync #install dependencides
  ```

* Run the Fresh Build inside the graphiti\mcp_server\ directory - Clear old Docker BuildKit cache layers
  ```
  docker builder prune -f
  
  # Force rebuild passing the necessary variables directly
  docker compose build --no-cache --build-arg GRAPHITI_VERSION="" --build-arg INSTALL_FALKORDB="false"
  
  # Launch your server and database stack
  docker compose up
  ```
